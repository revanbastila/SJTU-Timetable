## 定位结果与证据边界

修改前，先在未修复的共用组件上执行可控复现，记录 `软件/work/web-repro-1.14.25.log`，两个断言均失败：

1. 首页会话准备完成后，论坛帖子加载仍会重新进入通用 SSO 自动点击。原条件只检查 `preferSsoLogin` 和主机，未限定登录入口/首次引导；无按钮时 `_ssoAttempted` 一直为 false。旧选择器会按 350 ms 间隔重试，最多六次。如果当前 DOM 中出现匹配的 SSO 控件，就会启动新的认证跳转。可控场景日志为：

   ```text
   [fixture-web] auto-sso-check /t/topic/123 #7
   [fixture-web] unexpected SSO click on content -> home
   Expected: https://shuiyuan.sjtu.edu.cn/t/topic/123
   Actual:   https://shuiyuan.sjtu.edu.cn/
   ```

2. “重试”和顶部重新加载都调用 `_reloadFromStart`，末尾无条件 `loadRequest(widget.initialUrl)`，因此失败帖子重试实际加载 `/login`：

   ```text
   School web main-frame error: -2 fixture network offline shuiyuan.sjtu.edu.cn/t/topic/456
   [fixture-web] app.loadRequest shuiyuan.sjtu.edu.cn/login
   Expected: https://shuiyuan.sjtu.edu.cn/t/topic/456
   Actual:   https://shuiyuan.sjtu.edu.cn/login
   ```

3. 导航任务的 generation 原本只在返回、关闭时失效，普通导航、SPA URL 变化和重试没有取消旧的认证工作。旧 `onPageFinished`、错误、延迟检查也没有统一核对当前导航。
4. 图书馆恢复路径还有同类缺陷：重试清除了已接受的 HTTP 回退状态，导致用户重试 HTTP 子页面时又启动 HTTPS 升级。本版专项测试实际捕捉到了该循环并修复。
5. 图书馆/邮箱的 HTTP 升级处理原来没有先区分主框架与子框架，iframe 导航可能被提升为整个 WebView 的 `loadRequest`。专项测试加入了子框架不能重载顶层页面的检查。

以上是实际应用 Dart 代码在可控平台回调/页面行为下复现的缺陷。**当前没有手机现场日志，尚不能证明用户水源账号当时具体匹配了哪一个 DOM 控件，或所有线上跳转只由这一条链路触发。** 自动选择器的延迟尺度与现象相符，但不把这条推断写成线上实测结论。

## 实际修改

生产业务代码仅修改以下两个文件，另更新版本元数据：

- `lib/pages/authenticated_web_page.dart`
  - 接受新的顶层导航、开始加载和 SPA URL 变化时更新导航 generation，旧异步工作自动失效。
  - 重试保存的失败目标；普通重新加载优先使用当前 URL。保留完整路径、参数、片段和现有 WebView 实例，不重新打开初始主页。
  - 重试先停止旧加载、取消旧超时/延迟错误任务；异步读取当前 URL 或停止加载期间若发生新导航，则放弃旧重试。
  - 自动 SSO 选择只用于首次入口引导或明确的登录路径（包括 accounts/login 和 SPA 的 #/login）；已进入正常子页面后不重复扫描 SSO。
  - 同一 generation 只进行一次页面检查；新 generation 可以立即开始，不被旧检查阻塞。
  - 忽略与当前 URL 不符的完成/错误回调，以及该次导航已成功完成后的迟到错误。仍处理新的、真实失败的主框架加载。
  - 异步初始化在配置返回后核对 generation，避免较早的初始入口加载覆盖后来的导航。
  - 图书馆重试保留原允许主机范围内的 HTTP 回退及认证上下文，避免重新启动协议恢复循环；没有扩大明文主机白名单。
  - 子框架继续交由 WebView 导航，不将 iframe 升级为顶层加载。
  - 返回继续使用原生历史快照/跳转及原有认证中间页过滤；成功后更新当前 URL。移除返回完成后额外持续 900 ms 的 URL 拦截窗口，防止正常新导航被拦截。
  - 导航日志只记录主机、路径、事件和 generation，不记录查询参数、片段、Cookie、页面内容或凭据。
- `lib/services/school_web_auth.dart`
  - 自动 SSO、Canvas jAccount 选择、表单提交和填写增加可选 `expectedUrl`，执行 JavaScript 时再次核对正在操作的页面，避免已排队的旧动作作用于另一页面。
  - 这是对自动认证动作执行范围的检查，不锁定浏览 URL、不拦截正常网页跳转。原有选择规则、账号来源、Cookie 和表单行为保持原样；其他调用方未传入该参数时保持原行为。

没有新增 UI、弹窗或刷新提示，没有清除 Cookie/Session/网页历史，没有更换网站入口，没有禁用所有重定向，也没有增加“等固定时间后强制回主页/锁住帖子”的逻辑。现有网络截止时间、错误宽限及历史落点检查仍承担原来的超时/返回职责。
