## 补充修改：动态地点与教师之间增加空行

用户补充要求：动态显示界面的上课地点与教师姓名之间，从一行留白改为两行留白。

只修改 `week_page.dart` 的动态模式教师上方间距：地点与教师都存在时，使用两倍正文行高，并随系统文字缩放；静态模式仍为一行留白。缺少地点时不增加额外间距，原字体、字号、颜色、字重和其他布局保持不变。版本仍为 1.14.25 / 81。

此次补充修改后，40 项相关回归/组件测试通过（包含深浅色课表预览与原静态间距测试），Flutter analyze 无问题。相关记录为 `软件/work/tests-1.14.25-spacing.log`、`analyze-1.14.25-spacing.log` 和 `build-1.14.25-spacing.log`。下文 212 项全套测试是补充修改前的记录；本次仅对受影响范围重跑，手机验收仍按用户安排稍后进行。四个 APK、校验值与源码压缩包均随补充修改更新。

## Canvas 的实际同步机制

现有架构是本地客户端，没有可接收服务端事件并转发到手机的后台服务、推送令牌或校方管理员订阅。Canvas Live Events 的官方订阅需要管理员配置 SQS/HTTPS 数据流，不能把现有学生网页登录当成已经开通推送。因此本版沿用经过授权的现有 WebView Canvas 会话访问公告接口，没有重新登录或采集密码。

已经写入的优化：

1. 原查询窗口每次至少重复一周，现改为上次成功游标前两分钟的重叠窗口，并保留整个离线间隔；重叠内容按课程和公告 ID 去重，不重复加入消息。
2. 新课程目录触发重新建立基线。初次同步不对历史公告轰炸通知。旧账号退出后清理对应原生任务/缓存；提交前再次核对账号修订号，避免旧会话结果覆盖新会话。
3. 只有完整成功后才提交结果、游标和已见 ID。网络/认证/限流/服务端错误不覆盖上次成功消息；保留兼容接口回退，服务器错误不再放大成逐课程请求。
4. 原生任务写入缓存后向 Flutter 发更新信号；前台即时读缓存，恢复前台也先读缓存。沿用消息合并、排序、稳定 ID 和已读记录，不启动页面加载动画。
5. 新公告用稳定 ID 生成系统通知，显示 Canvas 及课程来源。遵循 APP 现有提醒关闭设置和 Android 通知权限；不自动弹出新的授权请求，关闭或未获权限时仅同步缓存。消息通知使用普通通知频道，不改变课程闹钟的行为。
6. 没有邮箱授权时不请求邮箱密码、不抓取页面中的密码、不伪造邮件消息。

实际频率和限制：

- APP 前台：名义每 2 分钟检查；网络耗时、已有检查未结束或原生失败退避可能延后。
- APP 后台：原生持久化 JobScheduler，周期 15 分钟、flex 5 分钟、要求有网络，且使用系统最小周期作为下限。即使 Flutter 页面未运行，仍由 Android 调度；并非 Activity 定时器。
- **没有达到严格后台每 2 分钟检查。** Doze、省电、后台限制、强制停止及会话过期可能进一步延后或停止。没有添加常驻前台服务、隐藏系统通知或滥用精确闹钟。
- 本次没有 Android 连接设备；以上频率是实际代码配置和官方系统约束，不能替代设备上的实际执行间隔测量。

## 交大邮箱的可行性与未实现部分

原 APP 只有 `mail.sjtu.edu.cn/modern/` 的认证网页入口，没有邮件 OAuth 客户端配置、`read_mails` 授权令牌、IMAP 连接或邮件推送订阅。

学校公开文档提供 `GET https://api.sjtu.edu.cn/v1/mails/` 和 `read_mails` 授权码范围，说明存在可申请的接口方案；但 APP 尚无该授权，网页登录 Cookie 不等于开放 API 令牌。另外文档结构示例含 `canvas.mail`，仍需向校方确认实际数据是否覆盖交大邮箱收件箱、分页和时间/增量语义。本次没有把它当成已可用的收件箱接口。普通 IMAP 文档要求邮箱密码，不符合本任务“不能为检查邮件读取/保存/传输明文密码”的约束，因此没有接入密码式 IMAP。

**邮箱新邮件自动进入消息模块、邮件后台同步、邮件通知及邮箱端到端测试均未完成。** 后续需要获得学校批准的邮件访问配置，确认接口对应的邮箱数据，再由用户自行完成授权；不应向对话发送密码或长期令牌。Canvas 和邮件真正的实时推送均未声称已经实现。
